# Слой гиперспектрометра: архитектура и принятые решения

Статус: архитектура согласована, код не реализован.

## 1. Назначение

Слой `optsim.spectral` моделирует работу гиперспектрометра и стоит над слоем
`optsim.physics`. Задача слоя: по спектральной сцене и траектории сканирования
получить кадры детектора, затем по ним собрать гиперкуб и восстановить сцену.

optsim используется как библиотека. Оптическую систему, её параметры и
эксперименты пользователь задаёт в своём скрипте, поэтому спектральный слой
не делает предположений о конкретной оптике.

## 2. Прибор

Схема: **щель → аксикон 1 → аксикон 2 → детектор**, все элементы разнесены
вдоль оси. Входной оптики нет.

- Щель — полукольцо радиуса `r` и ширины `w`.
- Система осесимметрична. Аксиконы дают радиальную дисперсию: на детекторе
  радиус ρ кодирует длину волны, азимут θ кодирует положение точки на щели.
- Это щелевой спектрометр в полярных координатах: строке щели соответствует
  θ, оси дисперсии — ρ.
- Полукольцо оставляет свободной вторую половину детектора под спектр.
- Объекты наблюдения круговые (условно Солнце).

## 3. Почему не собирался гиперкуб в прошлом проекте

Не хватало двух явных преобразований:

1. **Калибровка**: пиксель детектора → (λ, азимут φ на щели).
2. **Геометрия скана**: (положение прибора, φ) → (x, y) в сцене.

Каждый кадр даёт выборку вдоль дуги, а не вдоль строки. Без координат сцены
у каждой выборки куб не складывается. Обе функции в новой архитектуре —
отдельные объекты.

## 4. Принятые решения

| # | Решение | Причина |
|---|---|---|
| D1 | Спектральный слой не знает о конкретной оптике: `Hyperspectrometer` принимает готовые `System`, `Detector`, `Simulation` | optsim — библиотека, систему собирают и подбирают в пользовательском скрипте |
| D2 | Щель задаётся один раз объектом `SemiRing(r, width)`. Прибор сам ставит `Aperture` в z = 0, геометрия скана берёт радиус из того же объекта | Щель одновременно элемент оптики и геометрия выборки, значения не должны расходиться |
| D3 | Только численная калибровка, аналитической нет | С двумя разнесёнными аксиконами простая формула ρ(λ) неверна, переворот азимута зависит от схемы |
| D4 | Модель формирования изображения — подключаемая стратегия. Первая реализация когерентная | Когерентная модель повторяет прежний подход. Некогерентная (Солнце) будет добавлена позже без изменения интерфейсов |
| D5 | Когерентная модель: амплитуда `√I(x,y,λ)`, нулевая фаза | Совпадает с прежним «сцена × плоская волна» |
| D6 | Сцена по умолчанию в плоскости щели (z = 0). Расстояние сцена–щель — параметр, при ненулевом поле распространяется до щели | Входной оптики нет, точное положение сцены не определено |
| D7 | Щель неподвижна, движется сцена: сдвиг (линейный скан) и масштаб (радиальный скан) | Изменение расстояния до сцены меняет только масштаб. Пересчитывать сцену проще, чем щель |
| D8 | Первая траектория — линейный скан вдоль одной оси, радиальный — следующий этап | Проще проверять |
| D9 | Сцена подаётся в `System.run` как обычный `Source` (`SceneSource`) | `core`, `System`, `Detector` не меняются |
| D10 | Приоритет — количественное восстановление сцены, визуализация вторична | Требование пользователя |
| D11 | Длины волн обрабатываются пачками | При n = 4096 поле занимает ~134 МБ на одну λ |

## 5. Конвейер

```
SpectralScene ──► Scan (Pose…) ──► Hyperspectrometer.acquire ──► Frame (2D)
 [Nλ,H,W], dx      траектория       ImagingModel + System          │
                                                                   ▼
CartesianCube ◄── RawCube.to_cartesian ◄── assemble ◄── extract(Frame, Calibration)
 [Nλ,Y,X]         + карта покрытия        (pose,φ)→(x,y)   SpectralSlice [Nφ, Nλ]
```

## 6. Модули `optsim.spectral`

| Модуль | Содержимое |
|---|---|
| `scene.py` | `SpectralScene`: данные `[Nλ,H,W]`, шаг в метрах, длины волн. Фабрики синтетических сцен с известной истиной: точка, монохромный диск, диск с потемнением к краю и линиями поглощения |
| `rgb.py` | RGB → спектр через гладкий базис, отдельно от сцены |
| `source.py` | `SceneSource(Source)`: сцена с учётом `Pose`, пересэмплированная на сетку `Simulation`. Амплитуда `[Nλ,n,n]` |
| `geometry.py` | `Pose` (центр, масштаб), `LinearScan`, позже `RadialScan`. Функция (pose, φ) → (x, y) |
| `imaging.py` | `ImagingModel`: `Coherent`; позже `RandomPhase` (некогерентность усреднением по случайным фазам) |
| `instrument.py` | `Hyperspectrometer(slit, optics, detector, sim, model, scene_distance=0)`: `acquire(scene, pose) → Frame`, `scan(scene, traj) → list[Frame]` |
| `calibration.py` | `calibrate(hs, wavelengths) → Calibration`, отчёт о качестве (раздел 7) |
| `extraction.py` | Frame → полярная развёртка (`grid_sample`) → `SpectralSlice [Nφ, Nλ]` |
| `cube.py` | `assemble(frames, cal) → RawCube [N_поз, Nφ, Nλ]`; `to_cartesian(dx) → (cube [Nλ,Y,X], coverage)` |
| `metrics.py` | Сравнение с истиной, сглаженной до разрешения прибора: RMSE по каналам, SAM |
| `viz.py` | Синтез RGB из куба, срезы по λ, спектр в точке, полярная развёртка кадра |

Изменения в существующих слоях:

- `SemiRing` в `physics/elements/shapes.py` — общая фигура (кольцо с
  диапазоном углов).
- Больше ничего. `core`, `System`, `Detector` не меняются.

## 7. Калибровка

Повторяет калибровку реального прибора:

1. **Длина волны.** Монохроматическая плоская волна через всю щель для
   каждой λ из калибровочной сетки. На каждом азимуте ищется положение кольца
   ρ(λ, θ) (центроид). Это учитывает и искривление спектральных линий.
2. **Азимут.** Свет пропускается через узкий сегмент щели, определяется
   соответствие φ на щели ↔ θ на детекторе.
3. **Плоское поле.** Спектральная чувствительность по тем же прогонам.
4. **Функция рассеяния линии.** Ширина кольца → разрешение δλ(λ).

`Calibration.report()` даёт метрики для подбора параметров аксиконов:
спектральный диапазон на детекторе, δλ(λ), перекрытия, выход за край матрицы.

## 8. Геометрия скана

- Положение точки щели в сцене: `(x, y) = pose.center + R · (cos φ, sin φ)`,
  `R = r_щели / pose.scale`.
- Линейный скан полукольцом покрывает полосу высотой `R`. Точку с
  `0 < y < R` дуга пересекает дважды, при `s = x ± √(R² − y²)`. Отсюда
  избыточность и неравномерная плотность выборки, их показывает карта
  покрытия.
- Радиальный скан (позже) даёт сразу полярный куб (R, φ, λ), естественный
  для круглых объектов.

## 9. Восстановление в когерентном режиме

Детектор измеряет `|поле|²`, соседние точки щели интерферируют. Извлечение по
калибровке восстанавливает сцену приближённо, со «звоном» на резких краях.
Поэтому сравнение идёт со сценой, сглаженной до разрешения прибора.

Дальнейший путь: решение обратной задачи на основе модели прибора.
Когерентная модель линейна по амплитуде, и `Hyperspectrometer` служит прямым
оператором.

## 10. Пример использования

```python
sim = Simulation(Grid(n=4096, dx=2.5e-6))
optics = System([(z1, Axicon(period=p1)), (z2, Axicon(period=p2, converging=False))])
hs = Hyperspectrometer(
    slit=SemiRing(r=0.5e-3, width=10e-6),
    optics=optics,
    detector=Detector(z=zd, pixel=10e-6, n_pixels=400),
    sim=sim,
)

cal = calibrate(hs, wavelengths=np.linspace(450e-9, 700e-9, 26))
print(cal.report())

scene = SpectralScene.from_rgb("sun.png", dx=5e-6, wavelengths=cal.wavelengths)
frames = hs.scan(scene, LinearScan(x0=-2e-3, x1=2e-3, step=10e-6))
cube = assemble(frames, cal)
img, coverage = cube.to_cartesian(dx=10e-6)
compare(img, scene)
```

Имена и сигнатуры предварительные.

## 11. Порядок реализации

1. `SemiRing`, `SpectralScene` и синтетические сцены.
2. `SceneSource`, `Pose`, `LinearScan`, `Hyperspectrometer.acquire/scan` (когерентная модель).
3. Численная калибровка и отчёт.
4. Извлечение спектров, сборка `RawCube`, декартов куб и карта покрытия.
5. Метрики и сравнение с истиной.
6. RGB → спектр, визуализация.
7. Радиальный скан.

## 12. Открытые вопросы

- Положение сцены относительно щели (сейчас z = 0, параметр).
- Некогерентная модель: `RandomPhase` или банк функций рассеяния с
  циклической свёрткой по θ. Второй вариант строго верен только при сцене,
  изображённой в плоскость щели.
- Решение обратной задачи вместо прямого извлечения по калибровке.
